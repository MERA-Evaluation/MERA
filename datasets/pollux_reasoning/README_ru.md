# POLLUX Reasoning

## Описание задачи

**POLLUX Reasoning** — генеративный датасет для MERA Text 2.0: **117** тестовых заданий и **5** few-shot примеров (всего 122). Примеры отобраны из [POLLUX](https://arxiv.org/abs/2505.24616) по фильтру `Technical Problems` / `Hard` / `Общее`.

Датасет проверяет техническую генерацию и рассуждение: написание, изменение и анализ кода (SQL, Python, C#, C++, JavaScript). Ответ модели оценивается LLM-as-a-Judge (Pollux-4B-Judge) отдельно по каждому элементу `criteria`.

Тестируемые навыки: General Reasoning, Chain-of-Thought, Decomposition, Code Generation.

Авторы: Никита Мартынов, Анастасия Мордашева, Дмитрий Горбецкий, Данил Астафуров, Ульяна Исаева, Элина Басырова, Сергей Скачков, Виктория Берестова, Николай Иванов, Валерия Занина, Алена Феногенова

## Мотивация

Датасет предназначен для оценки способностей моделей решать технические задачи в свободной форме: SQL и код на Python, C#, C++, JavaScript — написание, правка и анализ.


### Ограничения

Датасет не предназначен для оценки формальной грамотности, лингвистического анализа или суммаризации. Охват ограничен техническими / кодовыми задачами, требующими многошаговых рассуждений.

### Для кого результаты

Результаты полезны создателям чат-ботов и помощников для бизнеса и бытовых сценариев, а также разработчикам систем, где важны навыки рассуждения и работы с кодом.

### Оцениваемые способности

- Адекватно понять техническую постановку и выбрать способ решения
- Сохранять логическую последовательность в ответе и в коде
- Проявлять здравый смысл при разборе условий и краевых случаев
- Писать и анализировать код на заявленных языках

## Описание датасета

- `test.json` — **117** тестовых примеров (`meta.id` 6–122)
- `shots.json` — **5** few-shot примеров (`meta.id` 1–5)
- Всего: **122**

Все примеры: `categories.meta = Technical Problems`, `difficulty = Hard`, `domain = Общее`. Типы задач: написать код, изменить код, проанализировать код; подтипы: SQL, Python, C#, C++, JavaScript.


### Поля данных

- `instruction` [str] — один из пяти wrapper-промптов из `dataset_meta.json` с плейсхолдером `{question}`
- `inputs.question` [str] — условие задачи (текст и/или код)
- `outputs` [str] — намеренно пустая строка; не эталон; ответ модели появляется на этапе оценки
- `meta.id` [int]
- `meta.prompt_id` [int] — идентификатор исходного промпта POLLUX
- `meta.source_instruction` [str]
- `meta.categories` — `difficulty`, `domain`, `meta`, `task_type`, `task_subtype`, `task_subsubtype`
- `criteria` [list] — критерии судьи: `criteria_name`, `criteria_description`, `rubrics`, `rubrics_example`
- `reference_answer` [str] — эталон решения или исправленного кода; передаётся судье при оценке

### Промпты

Для задачи подготовлено 5 вариантов промптов. Они распределены равномерно по примерам по принципу «один промпт на один пример». Каждый промпт задаёт свободную текстовую генерацию и требует ответ в формате `Ответ: <сгенерированный текст>`. Плейсхолдеры в фигурных скобках (в частности `{question}`) заполняются из полей внутри `inputs` для каждого вопроса. Тексты промптов хранятся в `dataset_meta.json` и продублированы в поле `instruction` каждого примера.

### Создание датасета
Датасет является подвыборкой из закрытой части сета POLLUX, дополняющей публичную версию: [POLLUX](https://arxiv.org/abs/2505.24616). Примеры отобраны по фильтру `Technical Problems` / `Hard` / `Общее`.

### Метрики

- `llm_as_judge`. На каждый элемент `criteria` выполняется отдельный вызов Pollux-4B-Judge через OpenAI-compatible endpoint. Баллы критерия — 0/1/2; итог примера — среднее баллов, делённое на 2.
