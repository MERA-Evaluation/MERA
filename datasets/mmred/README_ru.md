# MMReD

## Описание задачи

**MMReD** (Dense Context Reasoning Benchmark) — синтетический бенчмарк для оценки способностей языковых моделей к рассуждению на длинном контексте. Бенчмарк генерирует последовательности состояний комнат, в которых персонажи перемещаются между комнатами на каждом шаге. Модель должна агрегировать информацию по всей последовательности, чтобы ответить на вопрос о поведении персонажей.

Подмножество для MERA включает 5 типов вопросов Dense Context (DC) при 3 длинах последовательности (32, 64, 128 шагов) — итого 15 подзадач по 50 вопросов (750 вопросов).

Тестируемые навыки моделей: Long-context reasoning, Dense aggregation, Counting, Temporal tracking

Авторы: Борис Широких, Максим Куркин

## Мотивация

Существующие бенчмарки для рассуждений либо тестируют поиск иголки в стоге сена (нахождение одного факта), либо используют естественные тексты, где истинный ответ неоднозначен. MMReD заполняет этот пробел, оценивая рассуждение на плотном контексте — способность агрегировать информацию из множества наблюдений для получения одного ответа.

Это важно для оценки:
- LLM, работающих со структурированными данными большого объёма
- Способности моделей считать, отслеживать и сравнивать во временных последовательностях

Синтетическая природа данных обеспечивает идеальную эталонную разметку, отсутствие утечки данных и контролируемую сложность через длину последовательности. Более длинные последовательности требуют отслеживания большего числа состояний, что делает задачу прогрессивно сложнее.

Exact Match используется как метрика, поскольку ответы — однозначные слова или числа. Оценка строится на трёх уровнях: по подзадаче, по типу вопроса (взвешенное по длинам) и по всему бенчмарку (гармоническое среднее по типам).

## Описание датасета

Датасет содержит **750** примеров в **15** подзадачах (5 типов вопросов × 3 длины последовательности).

### Распределение по типам вопросов

Каждому примеру в поле `meta.categories.task_type` соответствует один из пяти типов:

| `task_type` | Тип вопроса | Кол-во | Доля |
|-------------|-------------|-------:|-----:|
| DC-SA-C | Кто провёл больше/меньше всего времени в одиночестве? | 150 | 20,0% |
| DC-SR-I | Сколько шагов X провёл в комнате Y? | 150 | 20,0% |
| DC-CC-I | Сколько шагов в комнатах существовала толпа (3+ человек)? | 150 | 20,0% |
| DC-WS-R | В какой комнате X провёл больше/меньше всего времени? | 150 | 20,0% |
| DC-WHS-C | Кто провёл больше/меньше всего времени в комнате X? | 150 | 20,0% |

### Распределение по длине последовательности

Каждому примеру в поле `meta.categories.seq_len` соответствует одна из трёх длин:

| `seq_len` | Кол-во | Доля |
|----------:|-------:|-----:|
| 32 | 250 | 33,3% |
| 64 | 250 | 33,3% |
| 128 | 250 | 33,3% |

Формат ответа — одно слово или одно число: имя персонажа, название комнаты или количество. Модель должна ответить в формате `Ответ: X`, где X — один токен.

### Поля данных

Каждый пример в датасете содержит следующие поля:

- `instruction` [str] — промпт-инструкция для модели, содержащая шаблон для вставки элементов вопроса

- `inputs` — входные данные, формирующие задание:
    - `context` [str] — последовательность шагов в формате JSONL: по одному объекту `{"step_id", "rooms"}` на строку
    - `question` [str] — текст вопроса

- `outputs` [str] — правильный ответ на вопрос

- `meta` — метаданные:
    - `id` [int] — номер-идентификатор вопроса в датасете
    - `categories` — категории признаков, характеризующих тестовый пример:
        - `task_type` [str] — код типа задачи (DC-SA-C, DC-SR-I, DC-CC-I, DC-WS-R, DC-WHS-C)
        - `seq_len` [int] — длина последовательности (количество шагов)
        - `atype` [str] — тип ответа: person, room или number

### Пример данных

```json
{
    "instruction": "Задача:\nПроанализируй перемещения и расположение персонажей по шагам.\n\nКонтекст:\nПоследовательность шагов в формате JSON показывает, какие персонажи находятся в каких комнатах.\n{context}\n\nФормат ответа:\nОтветь одним словом или одним числом в формате: Ответ: X\n\nВопрос:\n{question}\n\nОтвет:",
    "inputs": {
        "context": "{\"step_id\": 1, \"rooms\": {\"Кухня\": [\"Сандра\", \"Мария\"], \"Ванная\": [\"Иван\", \"Михаил\"], \"Сад\": [], \"Офис\": [], \"Спальня\": [\"Даниил\"], \"Коридор\": []}}\n{\"step_id\": 2, \"rooms\": {\"Кухня\": [\"Сандра\"], \"Ванная\": [], \"Сад\": [\"Даниил\"], \"Офис\": [\"Иван\", \"Мария\"], \"Спальня\": [\"Михаил\"], \"Коридор\": []}}",

```

### Создание промптов

Для задачи были подготовлены 10 промптов, которые были равномерно распределены по вопросам по принципу «один вопрос – один промпт». Шаблоны в фигурных скобках в промпте заполняются из полей внутри поля `inputs` в каждом вопросе.

### Создание датасета

Датасет полностью синтетический, сгенерирован процедурно:
1. На каждом шаге персонажи (Sandra, Mary, John, Daniel, Michael) случайно распределяются по комнатам (Kitchen, Bathroom, Garden, Office, Bedroom, Hallway).
2. Вопросы генерируются по шаблонам с верифицированными эталонными ответами.
3. Последовательности дедуплицируются через SHA-256 хеширование.
4. Каждая комбинация тип вопроса × длина последовательности содержит 50 примеров.

Сид: 0xBADFACE для воспроизводимости.

Код генерации: https://github.com/Fr0do/mmred

### Метрики

Оценка строится на трёх уровнях:

| Уровень | Группа / задача | Метрика | Агрегация |
|---------|-----------------|---------|-----------|
| 1 | Каждая из 15 подзадач (`mmred_dc_*_{32,64,128}`) | **Exact Match на подзадаче** | Среднее по 50 вопросам |
| 2 | Каждая из 5 групп по типу вопроса (`mmred_dc_sa_c`, …, `mmred_dc_whs_c`) | **Взвешенный EM по типу вопроса** | Взвешенное по длинам среднее по 3 длинам последовательности |
| 3 | Весь бенчмарк (`mmred`) | **Итоговая оценка MMReD** | Гармоническое среднее по 5 типам вопросов |

В логах оценки уровень 1 публикуется как `exact_match`; уровни 2 и 3 — как `em.dc_aggregate`.

**Exact Match на подзадаче** — доля ответов, точно совпадающих с эталоном (имя персонажа, название комнаты или число) в рамках одной подзадачи. Значение от 0 до 1.

**Взвешенный EM по типу вопроса** — объединяет оценки подзадач для длин 32, 64 и 128 с весами **2, 4 и 16** (более длинный контекст вносит больший вклад):

```
оценка_типа = (2 * EM_32 + 4 * EM_64 + 16 * EM_128) / (2 + 4 + 16)
```

**Итоговая оценка MMReD** — гармоническое среднее пяти типовых оценок. Штрафует слабые результаты на любом отдельном типе:

```
итоговая_оценка = 5 / (1/(s_1 + eps) + 1/(s_2 + eps) + ... + 1/(s_5 + eps)),  eps = 1e-6
```

где `s_i` — **Взвешенный EM по типу вопроса** для типа `i`.
