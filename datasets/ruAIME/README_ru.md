# ruAIME


## Описание задачи

Данный датасет содержит задачи из американского математического соревнования AIME (American Invitational Mathematics Examination) с 1983 по 2025 год. Задачи охватывают все ключевые разделы высшей математики: алгебру, геометрию, математический анализ, комбинаторику, теорию чисел, теорию вероятностей и статистику. Они требуют от модели глубокого понимания математических концептов, умения выполнять многошаговые преобразования, находить неочевидные связи и применять творческий подход к решению. Датасет предназначен для оценки способности моделей к сложным математическим рассуждениям в условиях, приближенных к олимпиадным.

Тестируемые навыки моделей: Mathematical reasoning, Problem solving, Algebraic manipulation, Multistep deduction, Pattern recognition

Авторы: Владислав Савенков, Антон Габов, Doubletapp


## Мотивация

Датасет ориентирован на оценку способностей продвинутых моделей к решению нестандартных математических задач высокого уровня сложности из различных областей математики. Он НЕ подходит для оценки базовых калькуляционных или текстовых моделей, не обладающих развитыми логико-математическими способностями.

Целевые пользователи — исследователи в области AI, оценивающие возможности моделей в области математического мышления, и разработчики образовательных систем. Результаты оценки покажут, может ли модель выступать в роли "решателя" олимпиадных задач, что критически важно для создания интеллектуальных репетиторов и ассистентов.

Оцениваемые способности:
1. **Глубинное понимание математического текста**: Модель должна корректно интерпретировать сложные формулировки условий, включая модули, радикалы, параметры, геометрические конструкции.
2. **Выбор стратегии решения**: Способность определить, какой математический аппарат (теорема, метод, прием) применить в конкретной ситуации.
3. **Многошаговые рассуждения**: Умение разбивать сложную задачу на последовательность логических шагов, сохраняя промежуточные результаты.
4. **Точность вычислений**: Минимизация ошибок в арифметических и алгебраических преобразованиях на пути к окончательному ответу.

Дизайн задач (точный числовой ответ) позволяет однозначно оценить правильность решения. Такой формат исключает субъективность при проверке и фокусирует оценку на конечном результате рассуждений модели. Метрика — доля правильных ответов (accuracy) — является строгой и интерпретируемой: она показывает, какую долю задач из набора модель может решить полностью и без ошибок.


## Описание датасета

### Поля данных

Каждый вопрос в датасете содержит следующие поля:

- `instruction` [str] — Инструкция для решения задачи;
- `inputs` — Вводные данные, формирующие задание для модели. Могут включать одну или несколько модальностей - видео, аудио, изображение, текст.
    - `question` [str] — Текст математической задачи;
- `outputs` [str] — Числовой ответ на задачу;
- `meta` — Метаданные, относящиеся к тестовому примеру, но не используемые в вопросе (скрытые от тестируемой модели).
    - `id` [int] — Уникальный идентификатор задачи в датасете;
    - `url` [str] — URL исходной задачи на AoPS Wiki;
    - `categories` — Категории признаков, характеризующих тестовый пример.
        - `contest_type` [str] — Тип математического соревнования;
        - `year` [int] — Год проведения соревнования;
        - `problem_id` [int] — Номер задачи в соревновании;
        - `math_domain` [str] — Математическая область задачи;
    - `solutions` — Решения задачи, могут содержать несколько вариантов решения.
        - `solution_i` — Один вариант решения задачи.
            - `id` [int] — Идентификатор варианта решения;
            - `text` [str] — Текст решения задачи


### Пример данных

```json
{
    "instruction": "Помогите мне, пожалуйста.\n\nРешите математическую задачу.\n\nПоследняя строка ответа должна содержать одно число в формате:\n\nОтвет: <число>\n\n{question}",
    "inputs": {
        "question": "Пусть $f(x)=|x-p|+|x-15|+|x-p-15|$, где $0 < p < 15$. Определите минимальное значение $f(x)$, принимаемое при $x$ из интервала $p \\leq x\\leq15$."
    },
    "outputs": "15",
    "meta": {
        "id": 1,
        "url": "https://artofproblemsolving.com/wiki/index.php/1983_AIME_Problems/Problem_2",
        "categories": {
            "contest_type": "AIME",
            "year": 1983,
            "problem_id": 2,
            "math_domain": "Алгебра"
        },
        "solutions": {
            "solution_1": {
                "id": 1,
                "text": "Сначала лучше всего избавиться от модулей.\nПри заданных условиях замечаем, что $|x-p|=x-p$, $|x-15|=15-x$ и $|x-p-15|=15+p-x$.\nСложив их, находим, что сумма равна $30-x$, которая достигает своего минимального значения (на заданном интервале $p \\leq x \\leq 15$) при $x=15$, давая минимум $\\boxed{015}$."
            }
        }
    }
}
```


### Промпты

Для задачи подготовлено 5 промптов, которые равномерно распределены по вопросам по принципу «один вопрос — один промпт». Промпты различаются по стилю обращения (неформальное *ты* / формальное *вы*) и требуют вывести одно число в формате `Ответ: <число>`. Шаблоны в фигурных скобках заполняются из полей внутри `inputs` в каждом вопросе.


Пример промпта:

```
Помогите мне, пожалуйста.

Решите математическую задачу.

Последняя строка ответа должна содержать одно число в формате:

Ответ: <число>

{question}
```


### Few-shot примеры

При оценке используются 2 демонстрационных примера из `shots.json` (`num_fewshot=2`). Они имеют тот же формат данных, что и тестовый набор, и иллюстрируют ожидаемый формат ответа.


### Создание датасета

Датасет создан на основе официальных материалов соревнования AIME за 1983-2025 годы. Источником данных выступил ресурс Art of Problem Solving (AoPS).

Процесс сбора и валидации включал:
1. Извлечение условий задач, их решений и ответов из HTML-страниц.
2. Полуавтоматическую проверку корректности извлечения числовых ответов и формул.
3. Ручную верификацию случайной выборки задач для каждого года на предмет соответствия оригиналу.
4. Перевод условий и решений на русский язык.
5. Структурирование данных в единый JSON-формат с четким разделением на условие, решения и мета-информацию.

Перевод на русский язык был выполнен с использованием API DeepSeek Reasoner. Основной задачей было создание параллельного англо-русского корпуса математических текстов с сохранением точности формул и естественности языка.

Процесс перевода осуществлялся специальным скриптом, который обрабатывал текстовые файлы с задачами. Модель получала четкие инструкции переводить только текст между специальными маркерами, сохраняя все математические выражения в формате LaTeX, теги boxed{} и первоначальную структуру. Скрипт был настроен для работы с большими объемами данных с возможностью остановки и возобновления обработки.

Для контроля качества проводилась выборочная ручная проверка перевода, которая подтвердила корректность обработки математических выражений и соблюдение требований. В результате был получен полный параллельный корпус качественных переводов, готовый для обучения русскоязычных моделей.
