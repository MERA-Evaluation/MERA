# Luzitania


## Описание задачи

**Luzitania** является набором данных для оценки возможностей языковых моделей решать математические задачи на русском языке. Набор фокусируется на многошаговых текстовых рассуждениях, измеряет способность модели прийти к корректному ответу по данному условию задачи.

**Ключевые слова:** math, reasoning.

Проверяемые навыки: Reasoning

Авторы: Ирина Пионтковская, Алексей Рухович, Кирилл Морозов, Максим Титов, Елена Энтина, Лаида Кушнарева, Кристиан Кузнецов, Александр Подольский, Семен Молоков, Тимофей Герасин, Артем Храпов, Юлия Скрипкарь, Никита Охотников, Павел Ефимов.


## Мотивация

Данный набор проверяет способность моделей строить последовательные рассуждения в математическом домене и приходить к обоснованным ответам. Уровень задач требует от моделей не терять нить рассуждения и иногда проводить долгие вычисления. Набор не предназначен для оценки мультимодальных способностей или понимания изображений: все условия задач текстовые. Набор помогает понять, насколько хорошо модель удерживает контекст, не "запутывается" в рассуждениях и приходит к обоснованному числовому результату.


## Описание датасета

### Поля данных

Каждый вопрос в датасете содержит следующие поля:

- `instruction` [str] — Промпт-инструкция для модели, содержащая шаблон для вставки элементов вопроса.
- `inputs` — Вводные данные, формирующие задание для модели. Могут включать одну или несколько модальностей - видео, аудио, изображение, текст.
    - `question` [str] — Текст вопроса.
- `outputs` [str] — Правильный ответ на вопрос.
- `meta` — Метаданные, относящиеся к тестовому примеру, но не используемые в вопросе (скрытые от тестируемой модели).
    - `id` [int] — Номер-идентификатор вопроса в датасете.
    - `source` [str] — строка, источник задачи (см. раздел Создание Датасета).

### Пример данных

```json
{
    "instruction": "Прочитайте задачу: \"{question}\". Найдите ответ. По умолчанию ответ — целое число. В случае нестандартного формата ответа следуйте указаниям в условии.",
    "inputs": {
        "question": "Вы заперты в комнате с единственным выходом — длинным коридором с рядом дверей и минными ловушками. Чтобы выбраться, нужно открыть все двери и обезвредить все мины. В комнате есть панель с 3 кнопками и инструкция. Красная кнопка устанавливает мину, жёлтая кнопка обезвреживает две мины и закрывает одну дверь, а зелёная кнопка открывает две двери. Изначально закрыты 3 двери и установлены 3 мины. В инструкции предупреждается, что попытка обезвредить две мины или открыть две двери, когда активна только одна мина или закрыта только одна дверь, сбрасывает систему в исходное состояние. Какое минимальное количество нажатий кнопок потребуется, чтобы выбраться?"
    },
    "outputs": "9",
    "meta": {
        "id": 999,
        "source": "example"
    }
}
```


### Промпты

Для задачи были подготовлены 10 промптов, которые были равномерно распределены по вопросам по принципу "один вопрос – один промпт". Шаблоны в фигурных скобках в промпте заполняются из полей внутри поля `inputs` в каждом вопросе.


Пример промпта:

```
Решите следующую задачу. Ответ запишите в виде целого числа, если в задаче не указано иное. {question}
```


### Создание датасета

Тестовый сет был собран из открытых источников с переводом условий задач на русский язык где необходимо. Ниже приведены все источники задач (то есть все возможные уникальные значения в поле `meta.source`) и количество задач из каждого источника в наборе.

| source | количество |
|--------|------------|
| olympiads | 131 |
| olympic_reason | 49 |
| MathArena | 34 |
| turgor | 30 |
| chinese_olympiads_2002_2006 | 7 |

#### olympiads

Задачи взяты из открытого набора [olympiads](https://huggingface.co/datasets/aslawliet/olympiads).

Фильтрация задач из этого датасета производилась следующим образом: сперва для всех задач из решений были извлечены ответы, затем были отобраны задачи с целочисленным неотрицательным ответом. Для набора этих задач запускалась рассуждающая модель средних размеров (GPT-oss-120B, reasoning "high", `max_length=65536` токенов) по 8 попыток на задачу (4 без использования `tool_call` и 4 с использованием `tool_call`). В текущий набор вошли задачи с долей успешных попыток `0 < x ≤ 50%` так, чтобы средняя длина ответов GPT-oss-120B была не менее 12k токенов, а самый короткий правильный ответ — не менее 10k токенов.

#### olympic_reason

49 олимпиадных задач разных стран, вышедших после апреля 2025 года. Подсэмпл этих задач можно использовать как отдельный валидационный набор для более ранних моделей, чтобы исключить утечку задач в трейнсеты.

#### MathArena

Отдельные задачи из наборов открытого лидерборда [MathArena](https://matharena.ai/).
В группу MathArena входят задачи из следующих открытых поднаборов:

- [ArXivMath_Feb_2026](https://huggingface.co/datasets/MathArena/arxivmath-0226)
- [ArXivMath_Jan_2026](https://huggingface.co/datasets/MathArena/arxivmath-0126)
- [ArXivMath_Dec_2025](https://huggingface.co/datasets/MathArena/arxivmath-1225)
- [apex](https://huggingface.co/datasets/MathArena/apex_2025)

#### turgor

Задачи «Турнира Городов».

[https://turgor.ru/problems/](https://turgor.ru/problems/)

#### chinese_olympiads_2002_2006

Книга «Mathematical Olympiad in China: Problems and Solutions», Xiong Bin and Lee Peng Yee
([PDF](https://phuylai.wordpress.com/wp-content/uploads/2009/10/mathematical-olympiad-in-china-problems-and-solutions.pdf))

Часть условий задач из всех источников может быть незначительно изменена с тем, чтобы в ответе получалось целое число.


## Оценка


### Метрики

Для агрегированной оценки ответов моделей используются следующие метрики:

- `Exact match`: Метрика Exact match вычисляет среднее по оценкам всех обработанных вопросов, где оценка имеет значение 1, если предсказанная строка точно совпадает с правильным ответом, и 0 в остальных случаях.
